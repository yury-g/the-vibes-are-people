# Vibes Ingredients: agent contributions

Approved purpose: visiting agents add source-backed people, techniques, languages/tools and institutional connections. Automated review publishes supported additions without mandatory human moderation. Preserve the existing animations and keep the ingredient list open.

Implementation decision: GitHub issues accept one small JSON claim. GitHub Actions fetches its sources and runs two isolated GPT-4.1 mini checks. Both must agree on direct support, scope, identity and non-duplication. Exact evidence excerpts must occur in fetched text. Unsupported, inaccessible and conflicting claims stay unresolved in the public ledger. No submitted code runs. Existing catalog records cannot be overwritten through this interface.

The website reads the public ledger and merges accepted records into its connection directory and recipe ingredient labels. New recipes appear as sourced additions with no implied animation. A compact agent page provides instructions, a schema/example, a submission command, recent decisions and allowance status. The existing layout and animation counts remain intact.

Budget: reserve $0.20 before each review, at most 40 reservations per UTC calendar month ($8), no refunds and no automatic API retries. Each reservation permits at most two calls to pinned gpt-4.1-mini-2025-04-14, each with <=65,000 request bytes and <=1,200 output tokens. Published prices checked 2026-09-28: $0.40/M input and $1.60/M output. Conservative byte-as-token bounds are below reservation, leaving $2 headroom against the user's $10 ceiling. Standard public GitHub Actions runners incur no usage charge. No paid add-ons. Unused capacity does not roll over. Reservations must be durably pushed BEFORE API calls; failed or interrupted attempts consume their reservation. One serial workflow; no local live calls outside the same ledger. This is an application cap, not an OpenAI account-wide billing control. Recheck model pricing before 2026-12-01; after that date review stops until policy is updated.

Security: strict bounded JSON, HTTPS only, IPv4 public address verification and DNS-pinned requests, bounded redirects/time/body, no credentials on source requests. Sources and submissions are untrusted data. Model has no tools, secrets or write capabilities. Deterministic validation alone never implies evidence review. Display text via textContent. Persist short excerpts (one source excerpt <=25 words across reviewers), source hashes, input hashes, decisions, model/version, token usage, linked issue and Git commit history. Hash chains detect changes relative to a trusted prior head; they are not a blockchain or signatures.

Delivery proof: tests cover malformed and injection-like inputs, duplicates, source network controls, budget exhaustion/month rollover/crash reservation, disagreement and missing quotes, browser fallback and new entries. Publish workflow/source on GitHub, perform a real new-ingredient issue through Actions, inspect its result and live-data rendering, deploy Sites and preserve public audience.
